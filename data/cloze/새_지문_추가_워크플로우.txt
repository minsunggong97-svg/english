새 지문 JSON 추가 워크플로우
===========================

이 설명서는 앞으로 새로운 모의고사 지문을 grammar-cloze.html 프로그램에 추가할 때 따라가면 되는 순서입니다.
기존 하드코딩 문제는 그대로 유지되고, 새 JSON은 추가 데이터로만 불러옵니다.
JSON에 문제가 있어도 프로그램 전체가 멈추지 않고, 문제가 있는 JSON 파일만 건너뜁니다.


1. 준비할 자료
-------------

새 지문을 추가하려면 아래 자료를 먼저 준비합니다.

1) 원문 지문 txt 파일
   - 예: 영어2/03_New_Passage.txt

2) 모의고사형 지문 분할 파일
   - 예: 영어2/03_New_Passage_모의고사지문분할.md
   - Part 1, Part 2처럼 지문을 나눠 둔 파일입니다.

3) 문장별 상세 문법 해설 파일
   - 예: 03_New_Passage_문장별_상세문법해설_Gemini_초안.md
   - 어법 빈칸과 서술형 배열 문제를 만들 때 참고합니다.


2. Gemini 프롬프트 준비
----------------------

아래 파일을 엽니다.

english/data/cloze/GEMINI_PROMPT_TEMPLATE.md

이 템플릿 안에 다음 내용을 채웁니다.

1) passageId
   - 새 지문을 구분하는 고유 ID입니다.
   - 영어 소문자, 숫자, 하이픈만 쓰는 것을 권장합니다.
   - 예: new-passage, climate-change, ancient-library

2) title
   - 지문 제목입니다.
   - 예: New Passage

3) groupLabel
   - 왼쪽 사이드바에 표시될 큰 지문 이름입니다.
   - 예: New Passage

4) 모의고사형 지문 분할 내용
   - *_모의고사지문분할.md 파일 내용을 붙여 넣습니다.

5) 문장별 상세 문법 해설 내용
   - *_문장별_상세문법해설_*.md 파일 내용을 붙여 넣습니다.


3. Gemini에게 JSON 생성 요청
---------------------------

Gemini에게는 GEMINI_PROMPT_TEMPLATE.md의 규칙을 그대로 전달합니다.

중요한 요청 조건은 다음과 같습니다.

- JSON만 출력하게 합니다.
- Markdown 코드블록을 쓰지 않게 합니다.
- schemaVersion은 반드시 1입니다.
- grammar, writing, vocab 세트를 모두 만들게 합니다.
- writing은 전체 문장이 아니라 서술형 예상 핵심 구문만 짧게 만들게 합니다.
- answer에 들어간 단어는 반드시 choices에도 포함되게 합니다.
- blank id는 passageId prefix를 붙여 중복되지 않게 합니다.


4. JSON 파일 저장
----------------

Gemini가 만든 JSON을 아래 폴더에 저장합니다.

english/data/cloze/

파일 이름은 passageId와 비슷하게 맞추는 것을 권장합니다.

예:

english/data/cloze/new-passage.json

저장 전에 최소한 아래를 확인합니다.

- 파일 전체가 JSON object 하나로만 되어 있는가?
- ``` 같은 Markdown 코드블록 표시가 들어가 있지 않은가?
- 쉼표가 빠지거나, 따옴표가 깨진 곳은 없는가?
- schema.example.json과 같은 구조인가?


5. manifest에 등록
-----------------

아래 파일을 엽니다.

english/data/cloze-manifest.json

새 JSON 파일 경로를 files 배열에 추가합니다.

예:

{
  "schemaVersion": 1,
  "files": [
    "data/cloze/new-passage.json"
  ]
}

여러 파일을 등록할 때는 쉼표를 넣습니다.

예:

{
  "schemaVersion": 1,
  "files": [
    "data/cloze/new-passage.json",
    "data/cloze/another-passage.json"
  ]
}

주의:

- 경로는 grammar-cloze.html 기준입니다.
- "english/data/cloze/new-passage.json"이 아니라 "data/cloze/new-passage.json"처럼 씁니다.


6. 앱에서 확인
-------------

grammar-cloze.html을 열어 확인합니다.

확인할 항목은 다음과 같습니다.

1) 왼쪽 사이드바에 새 지문 groupLabel이 보이는가?
2) Part 1, Part 2 등이 정상적으로 보이는가?
3) 어법 빈칸, 서술형 배열, 어휘 빈칸 모드를 전환해도 같은 Part가 유지되는가?
4) 문제를 풀고 채점했을 때 점수가 사이드바에 저장되는가?
5) 어휘 빈칸에서 난이도 필터가 정상적으로 동작하는가?


7. 문제가 생겼을 때 확인할 것
----------------------------

새 JSON이 보이지 않으면 아래 순서로 확인합니다.

1) cloze-manifest.json에 파일 경로를 정확히 추가했는가?
   - 올바른 예: data/cloze/new-passage.json
   - 잘못된 예: english/data/cloze/new-passage.json

2) JSON 파일이 실제로 english/data/cloze/ 안에 있는가?

3) JSON이 순수 JSON인가?
   - Gemini가 ```json 또는 ```를 같이 출력했다면 제거해야 합니다.

4) set id가 기존 문제와 중복되지 않는가?
   - 중복되면 해당 JSON 파일 전체가 무시됩니다.

5) writing, vocab 세트의 sourceSetId가 대응하는 grammar 세트 id를 정확히 가리키는가?

6) passageParts의 blank id와 blanks의 key가 정확히 일치하는가?

7) answer에 들어간 모든 단어가 choices 안에도 들어 있는가?

8) vocab 문제의 difficulty가 1~5 정수인가?


8. 실패해도 안전한 이유
----------------------

이 구조에서는 기존 내장 문제를 지우거나 이동하지 않습니다.

앱은 먼저 기존 하드코딩 문제를 기본 데이터로 준비한 뒤, manifest에 등록된 JSON을 추가로 불러옵니다.
외부 JSON 파일 중 하나가 실패해도 다음처럼 처리됩니다.

- manifest가 없으면 기존 문제만 실행합니다.
- JSON 파일을 찾지 못하면 그 파일만 건너뜁니다.
- JSON 문법이 깨져 있으면 그 파일만 건너뜁니다.
- 검증에 실패하면 그 파일만 병합하지 않습니다.
- 다른 정상 JSON과 기존 내장 문제는 계속 사용할 수 있습니다.


9. 추천 작업 순서 요약
--------------------

1) 새 지문 원문을 준비합니다.
2) 모의고사형 지문 분할 파일을 만듭니다.
3) 문장별 상세 문법 해설 파일을 만듭니다.
4) GEMINI_PROMPT_TEMPLATE.md에 자료를 넣고 Gemini에게 JSON 생성을 요청합니다.
5) 생성된 JSON을 english/data/cloze/ 아래에 저장합니다.
6) cloze-manifest.json의 files 배열에 "data/cloze/파일명.json"을 추가합니다.
7) grammar-cloze.html을 열어 새 지문이 보이는지 확인합니다.
8) 어법, 서술형, 어휘 모드와 점수 저장이 정상인지 확인합니다.


10. 파일별 역할
--------------

english/data/cloze/schema.example.json
- Gemini가 따라야 할 예시 JSON 구조입니다.

english/data/cloze/GEMINI_PROMPT_TEMPLATE.md
- Gemini에게 새 문제 JSON을 만들라고 요청할 때 쓰는 프롬프트입니다.

english/data/cloze-manifest.json
- 앱이 불러올 외부 JSON 파일 목록입니다.

english/data/cloze/*.json
- 실제 새 지문 문제 데이터 파일입니다.

english/grammar-cloze.html
- 문제 풀이 앱 본체입니다. 새 지문을 추가할 때는 보통 이 파일을 직접 수정하지 않아도 됩니다.
